M0服務骨架與契約

建立服務、產 DAL client、確立 Valkey 單寫者拓撲。DB 存取(MySQL/OceanBase)一律經 DAL;MongoDB 本服務直連。

M1ConfigSync — 設定投影

後台改動 → 本服務把 config / operator RTP 投影進 Valkey。config 就地更新不留版本(變更軌跡由 admin_audit before/after)。

M2DailyIncrementJob + PoolTicker — 每日增量與盤中注入

v2 核心:昨日 turnover 定今日總增量 → 盤中按排程規則漸進注入 input → 注入後的值即 Price → tick 交 msg-center。

M3SettleEngine — 中獎結算(核心)

GE 判定誰中、本服務原子決定拿多少。本服務提供 SettleWin gRPC + Lua 原子結算 + 落帳。v2:同步結算當場賠付,無 payout 狀態機。

M4通知 — 個人 inbox outbox

中獎個人通知 = 本服務寫 outbox_msg 表(經 DAL),msg-center poll 表處理。跑馬燈由 GS 發、不走 outbox。

M5Snapshot — 彩金滾動紀錄(MongoDB 直連)

v2:snapshot 移 MongoDB,本服務直寫直讀(不經 DAL),TTL index 解保留期。權威仍是 round / daily_increment / accounting_jackpot。

M6Recovery / Reconciliation — 恢復與對帳

卡單掃描補寫、round 補打、全域對帳偵測、Valkey 全損重建。WAL = 持久 spin 記錄 + 掃描器(照 FRB ReconciliationScan)。

M7報表 / 稽核

中獎名單、稽核檢視的讀取代理。

不在本服務範圍(跨團隊,僅依賴):① DAL 團隊實作 jackpot.proto 全 14 rpc(本服務為 caller);② GS 實作 SettleWin caller、win_id 推導、spin pending 標記、錢包 credit(win_id UNIQUE 去重)、跑馬燈事件發送;③ GS↔DAL 補 GameService.Credit 欄位(accounting_id+win_id+tier);④ msg-center 定案 event_type enum 值、poll outbox_msg、承載 SSE / msg-center-sse 分片輪掃;⑤ GE 側 Price/RTP feed 與 Prob=RTP/Price 計算;⑥ GameServer 側 game_math + MathFeatureFlags 遷移。待討論:盤中注入頻率與數值決定方式(規格待定)。細節見 規格與 Q&A。
