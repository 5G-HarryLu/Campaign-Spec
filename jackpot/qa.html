Q1tick 就是「注入後的池值即 Price」,對吧?是

正確。規格把三者畫上等號:注入後的池值 = Price = tick 推給前端的值。

  • Ch03 顯示 tick 卡:「注入後的池值即 Price(顯示=結算)」緊接「tick → msg-center SSE(≥5s)」。index.html:780
  • Ch02 / Ch03 lede:「盤中…漸進注入池值 — 注入後的值即 Price,顯示與結算共用」。index.html:492, 746
  • Ch02b 序列:分次 INCRBY input:{pool}:{tier},「注入後的值就是 Price」。index.html:696
精確度提醒:tick 是「讀池值」去推,前端 ≥5s 才更新一次。概念上 tick=注入後池值=Price 成立;實務上前端看到的是有節流(≥5s)的 Price 快照,不是即時同步。 index.html:780
Q2後到者拿 seed 而非第一筆當下累積的池值?(單 key 序列化 + Lua atomic)是

正確。兩筆同時中獎被序列化在單一 state:{pool}:{tier} key,由 Lua 原子腳本執行:

先到者 Lua:讀當下池值 = 派彩金額 → reset 到 seed → quota−− 後到者 Lua:讀到的已是「reset 後的 seed」= 派彩金額(非第一筆的滿池)
  • 「序列化在單一 key:先到者拿滿池、後到者拿 reset 後 seed」。index.html:721, 791
  • 「先到滿池、後到 seed(先到 = 先在本服務執行,非先中獎 — 寫進 game info)」。index.html:858
  • Lua 第一動作 SETNX settle:{win_id} 封雙結算窗;Lua 為原子執行。index.html:842, 858
結論:後到的池子數值會是 seed,不是第一筆當下 pool 累積的滿池值 —— 因為第一筆的 Lua 已把池 reset 到 seed,後到的 Lua 讀到的就是 seed。序列化 = Lua 原子 + 操作同一 key,把並發轉成確定的先後序。

R1匯率來源 = currency.fixed_rate

根據 currency.fixed_rate 決定「1 USD = 多少該幣值」。不另建 jackpot 匯率表,改用平台既有 currency.fixed_rate(v3:後台走 Valhalla CurrencyService 的 GetCurrencyFixedRatePageList / UpdateCurrencyFixedRate)。

  • Ch05 lede:「匯率用既有 currency.fixed_rate」。index.html:926
  • 結算換算:「以 currency.fixed_rate 換算一次(記憶體快取),USD/local 金額寫進 marker」。index.html:858
  • daily_increment:「以 currency.fixed_rate 換算(無版本欄位;需追溯由 currency 側記時間)」。index.html:1027
  • Ch06 後台·固定匯率:走 Valhalla CurrencyService(2 支,DAL 已建)。index.html:1188
R2累積速率來源 = jackpot_group_setting.contribution_rate

公式 turnover × fx → USD × 累積速率 = 今日總增量,其中累積速率取自 jackpot_group_setting.contribution_rate(v3:DAL 已定 DECIMAL(18,6),非 ppm)。

  • Ch05 jackpot_group_setting 欄位:「contribution_rate DECIMAL(18,6)(累積速率,入池;與中獎 RTP 是兩個獨立旋鈕,DAL 已定 decimal)」。index.html:971
  • daily_increment:「increment_microcents = turnover × 累積速率(contribution_rate)」。index.html:1028
注意兩把獨立旋鈕:入池的 contribution_rate(jackpot_group_setting)≠ 中獎 RTP(jackpot_group_operator.tier_rtp_json JSON,餵 GE 算 Prob=RTP/Price)。刻意不校核,營運手動調。 index.html:958, 971
R3盤中漸進注入的「頻率與數值決定方式」— 待討論

今日總增量不是一次進池:PoolTicker 按排程規則分次 INCRBY input:{pool}:{tier},池值一天內漸進長大,注入後的值就是 Price(顯示與結算共用)。

待討論(規格明標未定):注入的頻率與數值決定方式規格寫「每小時 / 線性 / 非線性,規則待定」、比例「待定」。此為尚未定案項,需與作者 / 會議討論後才能定實作。 index.html:492, 696, 746
已定的部分:① 落帳先於注入(UpsertJackpotDailyIncrement 冪等後才注入);② 注入進度另記防重,恰好注滿一次;③ first-write-wins,遲到 CDC 不回溯。 index.html:1031
